<product_requirements>
The application is a multi-tenant SaaS platform for dental offices, featuring an admin panel for super-admins and a brandable portal for individual dental practices.

**Core User Requirements:**
1.  **SamCart Payment Integration:** A critical requirement is a fully automated payment and onboarding flow via SamCart. When a user pays, the system must automatically create a new practice account, send a welcome email with login credentials, and allow them to access the app. This flow failed in production and was the highest priority fix.
2.  **Data Export:** The user needs a feature to export all patient correspondence data. This export must include patient name, email date, procedure sent, and doctor's name, be sortable by a date range, and available in both CSV and Excel formats.
3.  **Video Tutorials:** An admin-managed tutorial section is required for uploading and managing training videos. These videos must be viewable by practice users without distortion or playback errors.
4.  **Patient Status Workflow:** A clear and automated patient procedure status workflow is needed. The status should progress from Active (assigned but not sent) to Delivered (automatically set when a procedure is printed, emailed, or texted) and finally to Second (after a 24-hour follow-up email is automatically sent). Any confusing manual overrides, like the original Mark as Delivered button, must be removed.
</product_requirements>

<current_work>
The most recent and critical work involved diagnosing and fixing a catastrophic failure in the password reset and new user onboarding flow. After a live payment, the user was locked out of their account due to a series of cascading issues.

The core problem was traced to the backend API endpoint for validating password reset tokens, located at  within . This endpoint was incorrectly implemented to only search for the token in the  database collection. Since accounts created via SamCart are stored in the  collection, every reset token for a paying customer was being incorrectly marked as Invalid.

**The fix involved modifying this endpoint's logic to query both the  AND  collections**, ensuring that tokens associated with any type of account could be validated. After this code change was applied and the backend was restarted, the AI successfully sent a new password reset email to the user. The user was then able to use the link to change their password and was automatically logged into the correct application dashboard, finally resolving the weeks-long access issue.
